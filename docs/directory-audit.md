## 确认并整理的冗余发布内容

- 将 `public/assets/home/images/branding/logo-master.png` 移至 `docs/branding/logo-master.png`。母版为 1024 × 1024、542,805 字节，页面没有引用它；移动前后 SHA-256 一致。
- 将同目录的 `generation.md` 移至 `docs/branding/generation.md`，并更新素材路径说明。
- Vite 默认复制 `public/` 内容，原来两项会随构建公开发布；整理后静态产物少携带约 530 KiB 文件内容，页面实际使用的图标不变。

## 相同内容为何保留

业务文件中没有发现逐字相同的副本。三个上游包的 `LICENSE` 内容相同，但分别承载包内许可声明，保留原目录归属。

归档与当前文件之间存在三个相同内容分组：许可证、上游计分 reducer 和英文题库。归档保存下载快照，`vendor/` 提供当前测试与来源依据，两者职责不同；`data/` 已从 Git 和 Docker 构建上下文排除，无需为这点重复破坏归档。

`dist/` 中出现静态资源副本是正常构建行为。依赖、生成目录和归档体积不能直接等同于可删除的业务冗余。

## 可后续改进但未扩大处理的项目

- `src/style.css`、`src/home.css` 采用较长单行样式，并累积了一些覆盖规则，后续可以单独做格式化与样式梳理；本次没有借目录整理改动布局或交互。
- 根目录暂未提供依赖锁文件。需要提升构建可复现性时，应另行固定依赖并验证，不在目录整理中升级依赖。
- 离线 Docker 镜像是交付快照，校验通过不代表包含最后一次源码改动。生成新包属于单独的交付步骤。
