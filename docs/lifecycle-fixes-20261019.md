# 提交生命周期与关停修复

日期：2026-10-19。修复前复现见 [项目复测](retest-20261019.md)。

## 修复后的行为

1. **提交中的页面切换**：提交捕获发起时的页面版本、提交编号和草稿会话。成功响应仅清除对应提交的草稿；页面已经切换时不跳转、不覆盖当前结果，也不清除新草稿。失败处理不再直接访问可能不存在的消息元素。无论成功、失败或页面已切换，都在 `finally` 恢复提交状态。
2. **密钥匹配**：打开可写存储前，使用只读连接逐条验证数据库中已有的加密结果。错误密钥、混合密钥或损坏的加密链接会使启动失败，不替换密钥、不增加或修改业务记录。恢复配套原密钥后，旧链接和原编号重试恢复正常。访问结果链接时仍直接解密，不查询数据库。
3. **应用层超时**：请求与响应正文读取、校验共等待最多 30 秒，超时通过 AbortController 取消客户端请求，保留全部答案及原提交编号，提示重新提交并恢复按钮。服务端可能已经写入，重试依靠原回执返回原链接，不新增相同提交的记录。
4. **平滑关停**：停止接受新连接，关闭已完成请求的保活连接；在途请求继续完成请求体、事务和响应，随后才关闭 SQLite。默认等待 15 秒，超时关闭剩余连接并等待处理函数结束。钉钉工作进程停止取任务，保留未完成同步任务。Compose 停止宽限期为 25 秒。

原有约束保持：不同提交即使分数相同仍分别记录；同一次提交的重试不改结果、链接或时间；作答进度保存在浏览器，只有有效提交新增业务记录。
