# 匿名公开测评的请求保护

实现日期：2026-10-19。此保护属于项目本身，不依赖花生壳；直接运行 Node 和 Docker 部署都默认启用。前端继续匿名作答，无需注册、登录或填写个人信息。

## 默认规则

| 配置变量 | 默认值 | 行为 |
| --- | --- | --- |
| `APP_MAX_CONNECTIONS` | 128 | 应用进程最多保留的 TCP 连接数；多出的连接直接关闭 |
| `APP_MAX_CONCURRENT_REQUESTS` | 32 | 同时处理的 HTTP 请求数，含正在上传请求体的请求；超出返回 503 |
| `APP_REQUESTS_PER_SECOND` | 100 | 全进程所有路由每个窗口的请求数，包括静态文件；超出返回 429 |
| `APP_API_REQUESTS_PER_MINUTE` | 180 | 每个来源的全部 API 请求数，含解密、无效请求和提交重试；超出返回 429 |
| `APP_SUBMISSIONS_PER_IP_MINUTE` | 30 | 每个来源每分钟的新提交尝试数 |
| `APP_SUBMISSIONS_PER_SESSION_MINUTE` | 5 | 每个匿名会话每分钟的新提交尝试数 |
| `APP_SUBMISSIONS_PER_MINUTE` | 60 | 全进程每分钟的新提交尝试数 |
| `APP_BODY_TIMEOUT_MS` | 10000 | JSON 请求体接收的绝对时间上限，缓慢持续上传也不延长；超时返回 408 并关闭连接 |
| `APP_HEADERS_TIMEOUT_MS` | 10000 | HTTP 请求头接收时限，Node 负责关闭超时连接 |
| `APP_REQUEST_TIMEOUT_MS` | 15000 | HTTP 请求接收与连接无数据活动的超时配置 |
| `APP_MAX_PENDING_SYNC` | 500 | 钉钉未完成同步任务的上限；达到后新提交返回 503，不写入部分记录 |
| `APP_LIMITER_MAX_KEYS` | 10000 | 内存限流状态的键数量上限；过期清理，容量不足时返回 503 |
| `APP_TRUSTED_PROXIES` | 空 | 明确可信的代理 IP/CIDR，逗号分隔；默认不信任转发头 |

请求正文最多 16 KiB，包含分块上传；请求头最多 8 KiB，请求目标最多 4096 字符。单个保活连接最多处理 100 个请求。以上限制与时间配置在请求进入计分、加密和数据库写入之前生效；正文检查针对真实字节数，不能通过省略 Content-Length 绕过。

限流使用有界内存中的固定窗口。窗口结束后恢复，边界附近允许出现两个相邻窗口的请求；它不是平滑流量整形。429 及可恢复的 503 返回 `Retry-After` 秒数，客户端保留草稿并允许稍后重试。额外响应头包含 `nosniff`、禁止 iframe 嵌入及不发送 Referer，降低结果链接泄露等风险。

## 记录完整性与重试

- 原有回执匹配成功时直接返回原链接，不消耗新提交额度，也不受钉钉积压上限影响；仍受基础 API 频率、连接数和服务繁忙保护约束。
- 只有完整、有效且没有已有回执的提交才检查新提交额度。独立提交的分数即使相同也不会合并。
- 回执、业务结果、同步任务仍为一个事务。限流或积压拒绝会回滚，不产生部分记录、不改变历史时间或链接。已通过新提交额度后遇到实际写入故障，已消耗的额度不会退还，以免故障期间反复冲击存储。
- 不按分数去重，不清理旧结果、不删除待同步任务。积压消退后可用同一编号重试新提交。
- 普通访问和结果解密不访问业务数据库；限流状态只保存在内存，匿名 Cookie 只用于额度划分，不新增数据库字段。

匿名会话使用服务端签名的随机 Cookie（HttpOnly、SameSite=Lax），不包含答案、分数或身份信息。服务重启后限流状态重置，Cookie 可自动重发，不影响 localStorage 草稿和数据库回执。Cookie 不是登录凭据；清 Cookie、换浏览器可以得到新会话，因此同时设置 IP 和全局额度。IPv4 与其 IPv6 映射形式合并，同一 IPv6 /64 的地址共享来源额度。

## 反向代理与当前测试入口

默认使用 TCP 对端地址，忽略用户提供的 `X-Forwarded-For` 和 `Forwarded`。部署到服务器时，只将实际反向代理的地址加入 `APP_TRUSTED_PROXIES`。代理必须覆盖或追加真实客户端来源，且防火墙禁止绕过代理直接访问应用端口。

应用对 `X-Forwarded-For` 从右向左检查，跳过明确可信的代理，使用遇到的第一个不可信地址；不直接使用最左侧地址。地址和链长度都会校验。仅在直接对端可信时读取 `X-Forwarded-Proto: https` 并为 Cookie 设置 Secure；原生 TLS 连接也设置 Secure。

不能因为经过内网或 Docker 就信任所有代理来源。不要配置 `0.0.0.0/0`、`::/0` 来“解决”共享来源问题。花生壳当前只作为临时入口，未核实其转发头清理行为，所以保持可信代理配置为空；多个访问者可能共享映射服务的来源额度，这是安全默认值，后续在正式代理部署时明确配置。

未来正式域名应设置 `BASE_URL=https://实际域名`，使记录与钉钉分享链接固定使用站点地址，不依赖请求提供的 Origin。

`.env.example` 提供所有变量；Compose 已透传这些设置。数字配置必须为正整数，无效配置拒绝启动。请求头时限不能大于请求接收时限。默认额度是当前轻量服务的初始值，实际用户增长时按真实流量和硬件调整。

## 验证

```bash
npm run typecheck
npm test
npm run build
node --experimental-strip-types tests/production-reliability.mjs
node tests/storage-faults.mjs
```

新增测试覆盖：Cookie、IP、全局额度，忽略伪造转发头，正确代理链，IPv6 地址轮换，URL 路径别名，限流状态容量和过期恢复，重试不重复写入，独立相同分数分别记录，同步积压与恢复，API 只读访问限流，慢上传、并发上限、连接上限、慢请求头和分块超大请求。

浏览器回归 `tests/browser/request-guard.cjs` 使用隔离服务器：`rate` 模式配置会话每分钟 1 次，`backlog` 模式配置队列上限 1 且模拟未设置操作人的钉钉配置，验证 429/503 后 60 题与编号保留、刷新恢复和已有结果仍可访问。每个模式仅生成 1 条临时结果，不调用真实钉钉接口。运行时需要传入隔离服务器 URL、Playwright 模块位置和模式。

并发可靠性脚本会明确调高测试进程的频率额度，以继续验证 144 次请求的数据库并发与重试行为；低额度拦截行为由专门的请求保护测试覆盖，不在正式服务上进行洪泛测试。

## 边界

规则按单个 Node 进程计数；多副本部署时需在网关或共享限流服务统一计数。匿名限流可限制滥用速度，不能证明一个提交对应一位真实用户。验证码、入口带宽防护、CDN/WAF、服务器防火墙、容器资源限制和日志轮转应在后续服务器部署时配置。应用层保护不能阻止上游带宽先被占满，也不替代系统更新、密钥保管和备份。
