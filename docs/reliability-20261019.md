# 四项修复与可靠性复测

日期：2026-10-19。

后续更新：本文记录的提交超时与关停边界已修复，见 [提交生命周期修复记录](lifecycle-fixes-20261019.md)。下文保留当时的测试结果和边界。

## 修复结果

1. **旧标签页覆盖进度**：每个页面保留读取草稿时的存储快照。修改答案和提交前检查是否有其他页面更新；冲突时拒绝覆盖，加载最新草稿并提示用户确认。不会合并独立提交。浏览器复现中，新页面保存的 10 题在旧页面修改后仍为 10 题，刷新仍从第 11 题继续。
2. **异常成功响应清除答案**：客户端运行时校验量表版本、五维分数、细分结果、解释和链接格式，校验通过后才清理草稿。将实际提交成功后的响应替换为 HTTP 200 `{}`，60 题与原提交编号均保留；刷新后重试成功，同一次提交只记录一行。
3. **浏览器存储异常白屏**：结果页不初始化或写入草稿；作答页捕获存储访问、读取和写入异常，降级为内存作答并提示刷新会丢失进度。实际 Edge 中分别注入 QuotaExceededError 和 SecurityError，结果页正常显示，作答页可以继续使用。
4. **密钥缺失自动换密钥**：启动时只读检查已有记录。已有加密结果或回执但密钥丢失时，明确拒绝启动，不生成替代密钥、不改记录；恢复原密钥后，旧链接解密和同一次提交重试均成功。首次部署或空库仍可初始化密钥。

## 数据库写入范围

- 普通业务记录仅在 `POST /api/results` 验证完整答案后写入，结果与回执在同一事务内保存。
- 作答和刷新只处理浏览器草稿，不向数据库保存进度。浏览首页、作答页、结果页和分享链接均不会新增或更新记录。
- 加密链接直接由后端解密；关闭 SQLite 后仍能解密的自动测试通过，说明该路径不依赖数据库读取。
- 同一提交重试返回原链接，不更新原记录、链接或时间；不同提交即使分数相同仍分别记录。
- 已移除正常启动时批量改写历史结果链接的逻辑。首次建表和旧表结构迁移仍属于服务初始化；普通启动与访问不回写业务记录。
- HTTP 回归在首条有效提交后，给结果表和回执表添加禁止 INSERT、UPDATE、DELETE 的触发器，再执行页面访问、解密和 8 次并发重试，均通过且记录快照不变。

- Edge 浏览器故障回归通过：多标签页冲突、异常成功响应、存储不可用、慢请求中保留答案、断网及恢复后的重试。测试库仅有 3 次独立提交产生的 3 行记录。
- 完整 60 题流程另行验证：部分/完整草稿刷新、丢响应后重试、结果刷新与分享、随机提交、无效链接、375px 布局。剪贴板使用替身，并未验证系统剪贴板。

## 重复执行

所有命令在项目根目录执行。

```bash
npm run typecheck
npm test
npm run build
node --experimental-strip-types tests/production-reliability.mjs
node tests/storage-faults.mjs
```

`production-reliability.mjs` 使用临时 SQLite 和随机端口，结束后删除临时数据库。`storage-faults.mjs` 需要 Docker 和已有的 `bigfive-open-web` 镜像（可用 `TEST_DOCKER_IMAGE` 指定），创建独立临时容器与 tmpfs，结束后删除；不会挂载生产数据卷。

浏览器脚本为 `tests/browser/reliability.cjs`，需要 Playwright 与 Edge，单独运行，不包含在 `npm test` 内。必须向它传入隔离测试服务器的 URL；脚本会主动提交测试结果。Playwright 模块路径可以通过 `PLAYWRIGHT_MODULE` 或第三个命令行参数指定。

本轮机器可读结果保存在 `data/testing/reliability-20261019/`。完整恢复演练、跨浏览器真机、真实系统剪贴板和完整可访问性检查仍未执行。
