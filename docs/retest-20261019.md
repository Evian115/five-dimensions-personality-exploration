## 新复现的问题

### 1. P2：提交中切换页面后，异步响应仍操作当前页面

位置：`src/main.ts:182–222`，尤其第 201 行和第 215 行。`loadRoute()` 有路由版本保护，`submitResult()` 没有对应保护。

Edge 真实浏览器复现：先打开已有结果，经“重新测试”进入作答页，准备 60 题草稿；拦住提交请求，使用浏览器后退返回旧结果页，再放行响应。

- 网络失败：错误处理访问当前页面不存在的 `#message`，抛出 `Cannot set properties of null (setting 'textContent')`。`submitting` 没有恢复为 false；浏览器前进回作答页后，再点提交不发送请求。60 题草稿仍在，刷新能恢复。
- 提交成功：迟到响应执行 `history.pushState`，把用户已经返回的旧结果页强制切换到新结果页。

建议：提交流程持有独立的请求状态和页面版本，清理状态放入 `finally`；提交成功仍完成该提交自己的草稿清理，但只有页面仍属于该次提交时才更新界面或跳转。

本地复现与机器结果：`data/testing/review-20261019/navigation.cjs`、`navigation-run.mjs`、`navigation-report.json`。临时数据库最终 2 行：已有结果样本一行、成功分支提交一行；失败分支没有写入。

### 2. P2：合法长度的错误密钥不能在启动时被识别

位置：`server/result-cipher.ts:16–43`。已有数据但密钥缺失时已拒绝启动；密钥文件存在时只检查是否为 32 字节。

在隔离数据库中保存一条结果，将密钥文件换成另一份随机 32 字节密钥，再打开结果存储：

1. 启动成功，但旧链接和原提交重试失败。
2. 新提交仍成功，写入使用另一份密钥的结果链接。
3. 恢复原密钥后，旧链接恢复，新写入的链接反而不能解密。

这是备份、迁移时误配密钥的风险，本次没有发现正式环境密钥异常。

建议：启动开放写入前，校验密钥与已有加密结果或持久密钥校验信息是否匹配；不匹配时拒绝启动，提示恢复同一套数据库与密钥。单纯检查文件存在和长度不够。

本地复现与结果：`data/testing/review-20261019/key-probe.mjs`、`key-report.json`；只改临时目录里的密钥，结束后删除临时库和密钥。
